Security and data handling

Read-only is the operating boundary.

Neraium observes approved operational data. It does not write to control systems, issue commands, change setpoints, or control equipment.

Architecture boundary

Existing control systems remain separate.

The analysis path is defined around approved data sources and a documented review workflow.

  1. 01 / Owner

    Source approval

    The environment owner identifies the permitted system, signals, period, and transfer method.

  2. →
  3. 02 / Access

    Read-only ingestion

    Historical files or an approved source provide observational data without a write path.

  4. →
  5. 03 / Analysis

    Scoped processing

    Only the agreed system and data are included in the assessment or monitoring scope.

  6. →
  7. 04 / Review

    Human-reviewed output

    Findings and supporting evidence are provided to authorized reviewers.

Control boundary: no control-system credentials or write permissions are required for a historical assessment.

Data handling

Decisions are made before data moves.

  1. 01

    Define the minimum scope

    Agree the selected system, signals, time window, and operating question.

  2. 02

    Approve the transfer path

    Use a customer-approved export, secure transfer process, database path, or read-only API.

  3. 03

    Set access and review roles

    Identify who may provide data, review findings, and receive assessment outputs.

  4. 04

    Agree retention and closeout

    Document retention, return, or deletion expectations for the selected engagement.

Assessment controls

Practical controls for a bounded review.

01

Least data needed

The first assessment is limited to the signals and history needed for the agreed system question.

02

Named operating owner

Source approval and engineering review remain with the organization responsible for the system.

03

Separated outputs

Validation examples, data-quality observations, and system-behavior findings are labeled distinctly.

Deployment path

Historical first. Live only after review.

A historical assessment can be completed without any persistent source connection. If live monitoring is later justified, its authentication, network path, access controls, and retention are reviewed as a separate deployment decision.

No implied certification
  • Security requirements are reviewed per environment
  • Deployment controls depend on the approved architecture
  • No compliance certification is claimed on this page
  • Customer security review remains authoritative
