Security and deployment

Read-only by design. Explicit at every boundary.

Neraium is designed to remain outside the control path with customer-approved data sources, least-privilege access, no command authority, and deployment controls that are documented for the selected environment.

  • No setpoint changes
  • No equipment control
  • No autonomous commands
  • No administrative credentials for initial historical evaluation

Reference architecture

Telemetry moves toward analysis. No control path returns.

The initial workflow can use a customer-approved historical export. Any later source access must be explicitly approved and read-only.

Implemented operating principles

Conservative by default.

Read-only architecture

Analysis has no control authority.

Neraium does not change setpoints, issue commands, override equipment, or sit in a required control loop.

Least privilege

Request only what the evaluation needs.

An initial Historical Evaluation does not require live access or administrative credentials.

Customer-approved telemetry

Scope is agreed before transfer.

The system, signals, history, context, transfer method, and analysis boundary are discussed before data exchange.

Public inquiry boundary

No operational data through this website.

The public form prepares an email draft and instructs visitors not to include telemetry, credentials, diagrams, network information, or sensitive system details.

Deployment boundaries

Controls are verified for the selected environment.

A customer-hosted option can keep approved data and analysis inside a customer-controlled boundary. Exact controls depend on the selected deployment and must be documented rather than assumed.

Hosting and isolation

Confirm where analysis runs and which network boundaries apply.

Identity and access

Document approved roles, least-privilege access, and administrative boundaries.

Data protection

Confirm transfer, encryption configuration, retention, and deletion requirements.

Auditability

Define the logging, review, and customer-specific evidence required.

Claims not made

Security credibility requires precision.

Neraium does not claim certifications, assessments, or controls that are not documented. Independent assessments and customer-specific audits are evaluated separately.

  • No SOC 2 claim
  • No ISO 27001 claim
  • No FedRAMP claim
  • No penetration-test claim
  • No universal encryption or compliance claim
  • No supported-integration claim implied
