Security and Deployment

Read-only by design and outside the control path.

Neraium is designed for conservative OT and enterprise review: customer-approved data paths, no command authority, explicit deployment boundaries, and human engineering, operations, and maintenance review before action.

Reference architecture path

The reference model keeps analysis separate from control authority and makes customer-approved data handling explicit.

Approved export or read-only sourceCustomer-approved analysis environmentEvidence PackageHuman review and field judgment

Operating boundary

Neraium is read-only and outside the control path. It does not change setpoints, issue commands, override equipment, or request administrative credentials for an evaluation.

Customer-hosted deployment

A customer-hosted option can keep approved data and analysis inside a customer-controlled boundary. Exact hosting, isolation, encryption, retention, and audit controls are confirmed for the selected deployment.

Public inquiry boundary

The public form does not upload information to the website. It prepares an email and instructs visitors not to include telemetry, credentials, security diagrams, or confidential operating details.

Deployment-dependent controls

Data paths, encryption configuration, auditability, isolation, retention, identity controls, and network boundaries must be documented and verified for each customer environment.

Assessed separately

Independent security assessments, formal compliance controls, and customer-specific audits are planned or assessed separately unless documented for a deployment.

Claims not made

Neraium does not claim SOC 2, certifications not held, autonomous diagnosis, root-cause certainty, guaranteed savings, guaranteed downtime reduction, or control-system authority.
