Operational problem

Important changes can appear before a threshold alarm makes them obvious.

Facility systems are interconnected. A reading can remain inside limits while its relationship to load, pressure, temperature, command, or delivered output changes persistently.

Traditional monitoring asks

“Did this measurement exceed a threshold?”

Neraium asks

“Has the system’s behavior persistently changed, and what evidence supports that conclusion?”

What Neraium does

Relationship analysis organized for investigation.

Neraium evaluates approved historical exports or approved read-only sources from operational telemetry environments. It focuses on relationships rather than isolated points, persistence rather than transient noise, and explicit limitations rather than overconfident diagnosis.

Persistent behavior changes

Identify changes that remain across comparable operating periods.

Operating Context

Keep findings tied to load, mode, schedule, weather, staging, and known maintenance when those fields are available.

Evidence Packages

Package supported findings, limitations, confidence notes, and starting points for human review.

Evidence Package example

A concise engineering artifact, not a decorative dashboard.

Illustrative chilled-water pumping example. This is not customer data and it does not assert a diagnosis.

EP-CHW-017

Pump power and delivered flow relationship weakened under comparable operating conditions.

Illustrative only
System
Chilled-water secondary pumping loop.
Behavioral Finding
Pump power increased relative to delivered flow and persisted across comparable operating periods.
Earliest Supported
Example timestamp: 2026-05-14 02:10 local, based on available telemetry.
Operating Context
Comparable load band, same operating mode, similar commanded speed range.
Supporting Evidence
Power-flow residual shift, pressure-flow response change, repeated across illustrative operating windows.
Confidence notes
Persistence: strong. Context match: moderate. Instrument agreement: partial. Explanation certainty: unknown.
Evidence Limitations
Telemetry cannot distinguish hydraulic restriction from pump-performance degradation.
Recommended Starting Point
Verify valve position, inspect strainer differential pressure, and confirm commanded speed matches actual speed.

Security and deployment

Read-only by design and outside the control path.

Neraium does not operate equipment, change setpoints, override controls, or replace engineering judgment. Deployment controls must be confirmed for each customer environment.

Implemented site-level boundary

The public evaluation flow requests practical scoping data only and does not ask for telemetry, credentials, diagrams, guest, payment, gaming, surveillance, or reservation data.

Deployment-dependent controls

Isolation, encryption, customer-controlled infrastructure, and read-only source access depend on the selected deployment architecture and customer requirements.

Not claimed here

This website does not claim completed SOC 2, formal compliance certification, autonomous control, root-cause certainty, or guaranteed savings.
