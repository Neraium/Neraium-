What Neraium detects

Changes that deserve a closer look.

Findings describe observed behavior. They do not diagnose a specific failure.

01 / Behavior

Persistent relationship change

Signals no longer move together as expected.

02 / Signal integrity

Possible instrumentation issue

Sensor drift, stale values, timing problems, flatlines, or disagreement between related measurements.

03 / Context

Unexplained system change

Behavior no longer matches known operating modes, schedules, staging, maintenance, or demand.

How it works

From existing data to reviewable evidence.

A separate analysis path sits alongside existing controls and alarms.

  1. 01

    Connect existing data

    Historian exports, BAS, SCADA, CSV, databases, controllers, or approved read-only APIs.

  2. 02

    Learn operating relationships

    Build a baseline of how signals behave together under normal conditions.

  3. 03

    Detect persistent divergence

    Filter out short-lived noise and normal operating changes.

  4. 04

    Present evidence

    Show timing, affected relationships, persistence, data quality, and investigation context.

Operating boundary

Built to support engineering judgment

Neraium is an additional set of eyes for complex operations. The engineering team determines what the evidence means and what happens next.

  • Read-only by design
  • Never controls equipment
  • Findings require persistence
  • Data-quality issues remain separate
  • Supporting evidence stays visible
  • Engineers remain in control

Where it applies

Grounded in systems with operational telemetry.

Fit depends on signal coverage, operating context, and a review question worth testing. Each system is evaluated on its own data.
