# Private Ubuntu terminal exchange

Run `python3 /home/ubuntu/Neraium-/scripts/zoho-contact-setup.py` in your own Ubuntu terminal, with terminal recording/session logging off. Do not run it through Codex's tool terminal, `script`, redirected input/output, a debug wrapper, or an input recorder. The command contains no secrets and is safe to enter in shell history. The client ID, client secret and authorization code are collected by hidden terminal prompts, not shell commands or environment variables. Do not paste those values into chat. Python core dumps are disabled; request/exception bodies are suppressed; redirects and environment proxies are refused.

Enter the exact accounts server associated with the Neraium Self Client. Supported servers: accounts.zoho.com (us), accounts.zoho.eu (eu), accounts.zoho.in (in), accounts.zoho.com.au (au), accounts.zoho.jp (jp), accounts.zohocloud.ca (ca), accounts.zoho.sa (sa), accounts.zoho.uk (uk). There is no region default. HTTPS POST goes to that server's `/oauth/v2/token` with URL-encoded credentials in its body.

Choose `inspect` only for a code scoped exactly `ZohoMail.accounts.READ`. Choose `send` only for a separate code scoped exactly `ZohoMail.messages.CREATE`. Scope selection is your confirmation of the scope generated in the console; the helper cannot infer scope from the opaque authorization code. Use the same Neraium-specific Self Client and signed-in mailbox owner for both grants. Never use PPCLV credentials. If the already-generated code has expired, generate a fresh code immediately before the hidden prompts. Either grant may be exchanged first, preserving a fresh send grant while inspection remains pending. Run the helper again for the other grant.

The helper stores production credentials at `/home/ubuntu/.config/neraium/zoho-contact.json`, setup-only inspection credentials at `zoho-contact-inspection.json`, and selected account evidence at `zoho-contact-verification.json`. The directory must be owner-owned mode 0700; files are owner-owned mode 0600. It refuses existing production-token replacement. Inspection credentials are never included in Worker configuration. Authorization codes and access tokens are not persisted. No full account response or mailbox contents are exported.

Inspection requires exactly one Zoho mailbox owned by craig@neraium.com or website@neraium.com, enabled account/mailbox, outgoingBlocked:false, confirmed website@neraium.com email entry, and an active sendMailDetails entry for that sender. A dedicated website mailbox is reported as such rather than called an alias. If any condition fails, configuration preparation remains held; inspect the existing Zoho mailbox settings. No aliases are modified and no email is sent by the helper.

After both grants and matching client/region evidence exist, the helper adds the numeric account ID to the private production file and writes `.planning/contact-activation/zoho-verification-summary.json` (selected nonsecret evidence only) and `wrangler.zoho-prepared.jsonc` (review configuration only). Share only the completion status, file path and region in chat. Codex may read the sanitized summary; it must not print the private files.

The prepared configuration preserves both false flags, ASSETS, EMAIL destination restriction, Turnstile, rate limiter and domain/routes. It adds the verified ZOHO_DATA_CENTER public variable and requires four Zoho secret names. It has repository-root-relative asset/main paths: do not deploy it directly from `.planning/`. Integrate through a reviewed, strict preflight only after sender verification. Secret installation must use protected stdin/API bodies and only the production send-only credential file.

Public activation remains held until actual controlled inquiry receipt, live Turnstile/rate verification and explicit approval of CONTACT_DELIVERY.md's exact retention proposal with forwarding/copy inventory. Provider send acceptance is not receipt; do not retry an ambiguous delivery automatically.
